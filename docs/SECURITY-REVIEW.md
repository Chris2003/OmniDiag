# Security review (Phase 4)

One row per review item from [ROADMAP.md](ROADMAP.md) (Phase 4: "Security review with a test
per item"). Every finding is fixed with a test, or documented with a reason. Status values:
**fixed** (a defect was found and fixed), **verified** (no defect found; a test now guards
it), **documented** (accepted limitation, see the linked document).

## Content and import

Tests: `Tests/Security.Content.Tests.ps1` (deterministic, OS-independent, no network).

| item | finding | fix | test | status |
|---|---|---|---|---|
| HTML report encoding | Every session value was already HTML-encoded (`WebUtility.HtmlEncode`, attribute values are fixed template text, the brand color is validated as `#RRGGBB`, the logo is a base64 `data:` image with a fixed MIME type). The report has no script, inline JSON, event handler, or `href`. Robustness defect: a timeline / event-group time or a scan duration that is not a date / number (imported or hand-edited session) made the HTML export throw. | `Format-OmniHtmlTime` renders non-dates as encoded text; the duration is parsed invariantly and encoded (`src/Reporting/Html.psm1`). | `Report encoding: XSS payloads in every field` - payloads (`<script>`, `"><img onerror=`, `javascript:`, `</script>`, `{{...}}`, U+2028/U+2029, CDATA, comments) in every field of a factory-built session and of a crafted v1 report file; asserts only the template's own tags and attributes exist, no `on*=`/`javascript:` attribute, and each field is shown encoded. | verified (robustness fixed) |
| Markdown report encoding | Text was HTML-encoded and Markdown-escaped, but line breaks were only removed in table cells: a title, component, module name, or brand with a line break started its own Markdown block (heading, fence, table, list). | PDF report encoding | Literal strings escape `\`, `(`, `)` and drop control characters; the brand color is validated. No defect. | - | Same Describe: a `) Tj ... ET BT (` payload stays inside string literals (a PDF tokenizer counts `BT`/`Tj`/`ET` outside literals). | verified |
| JSON report encoding | `ConvertTo-OmniJsonText` writes ASCII-only JSON (`\uXXXX` outside printable ASCII, so U+2028/U+2029 cannot break a JavaScript consumer). No defect. | - | Same Describe: ASCII-only, valid, payload round-trips exactly. | verified |
| CSV formula injection and quoting | Only cells whose very first character was `= + - @ TAB CR` were neutralized: leading whitespace or quotes (`' =cmd'`, `'"=cmd'`), a leading LF, and the full-width forms U+FF1D, U+FF0B, U+FF0D, U+FF20 passed. | Redaction correctness | A seeded property-based test (random host, user, NetBIOS and DNS domains, e-mail, IPv4, IPv6, MAC, SID in 31 surrounding-text templates, random case, in every session field and in options and the base name, exported to every format with `-Redact`) found leaks: every detector (names, SIDs, MACs, IPv4, IPv6) rejected a match glued to an escape sequence - after a URL escape (`%5Cjdoe`, `jdoe%40contoso.com`, `%2010.20.30.40`, `%20fe80::1`) or a JSON escape kept as text (`\njdoe`, `\tS-1-5-21-...`, `\u0022ACME-WS-042`). A JavaScript model of the detectors leaked in 7432 of 26040 generated cases before the fix and 0 after. | `$script:OmniRedactEscapeBoundary` admits a match start right after `%XX`, `\uXXXX`, `\n`, `\r`, `\t` for terms and all pattern detectors; an IPv6 candidate after `%` is retried without the escape's two hex digits (`src/Core/Redaction.psm1`). Limitations added to [REDACTION.md](REDACTION.md). | `Redaction: property-based leak test across every format` (4 seeded iterations, >400 embedded identifiers each: zero originals in any file, ZIP entry, or file name; one pseudonym per value in every spelling; only the context's pseudonyms appear) and `Redaction regressions: identifiers glued to escape sequences`. | fixed |
| Session import (fuzzing and validation) | `Import-OmniSession` read files of any size, let PowerShell 7 parse nesting up to 1024 levels, accepted wrong JSON types silently (a string `Results` became an array of strings; objects where text belongs flowed into exporters), unrolled a top-level JSON array on PowerShell 7, and failed with assorted error types (string throws, cast and parser exceptions). Strings were never evaluated (verified). | Size cap (64 MB) before reading; nesting cap (100) checked on a string-free bracket skeleton before parsing (linear, regex timeout); one JSON object required; shape validation of the v1 report and native session (scalar / object / array per member, required `modules` / `Results`, `schemaVersion` `1.x.y`); every failure is one `System.IO.InvalidDataException` with error id `OmniDiag.SessionImportInvalid` (`src/Core/Evidence.psm1`, documented in [SCHEMA.md](SCHEMA.md)). | `Session import: targeted malformed input` (truncation, depth 150/1000/5000, brackets in strings, 1.5 MB string, 64 MB cap, 39 wrong-type members, unknown versions, missing members, non-objects, nulls, BOMs, invalid UTF-8, NUL, duplicate keys, `$(...)` payloads exported to every format) and `Session import: deterministic fuzzer (200 cases)` (seeded mutations of the golden v1 report and a native session; each case loads a well-formed session or throws the documented error, in under 20 s). | fixed |
